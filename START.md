### Два расширения к VS Code

Расширения это дополнения к редактору. Сам по себе VS Code про Python ничего не знает, он умеет работать с любым языком, и понимание конкретного языка добавляется отдельно. Ставятся они так: слева иконка с квадратиками (Extensions), в поиске набрать название, нажать Install.

**Python, от Microsoft.** Это то, что превращает редактор из блокнота в редактор кода. Он подсвечивает синтаксис разными цветами, подчеркивает ошибку красным до запуска, подсказывает названия функций, когда ты начинаешь их набирать, и показывает внизу, каким именно Python будет запускаться файл. Без него код выглядит как серый текст, и опечатку ты увидишь, только когда программа упадет.

**Git Graph, от mhutchie.** Рисует историю проекта картинкой: точки это сохранения, линии показывают, как одно выросло из другого, у каждой точки видно, кто и когда ее сделал. То же самое можно узнать командой в терминале, но списком строк. На занятиях мы смотрим историю именно им, потому что картинку понимать быстрее. Открывается внизу слева кнопкой Git Graph или через поиск команд.

### Терминал: что это вообще такое

Терминал это окно, куда команды компьютеру пишут текстом, а не мышкой. Набрал команду, нажал Enter, компьютер ответил текстом же. Все, что делается кнопками, можно сделать командой, но не наоборот: многие вещи кнопок просто не имеют.

Программисты работают в нем постоянно по одной причине: команду можно записать, передать другому человеку и повторить через год слово в слово. Объяснение «нажми вон туда, потом вон сюда» так не передается.

В VS Code терминал встроен: меню Terminal вверху, пункт New Terminal, и он открывается внизу окна, сразу в папке твоего проекта. Отдельную программу открывать не нужно.

### Git Bash вместо стандартного терминала

По умолчанию в Windows терминал свой, со своими командами. Вместе с Git ставится другой, Git Bash, и на занятиях мы пользуемся им.

Что это дает: команды в нем такие же, как на компьютерах, где работают настоящие разработчики, и такие же, как у меня на экране на занятии. Скопировал команду отсюда, вставил к себе, она сработала. В стандартном терминале Windows часть команд называется иначе, и половина примеров из интернета там просто не работает.

Как переключить, один раз: открыть терминал в VS Code, рядом с плюсом справа вверху панели терминала нажать стрелочку вниз, выбрать **Select Default Profile**, в списке выбрать **Git Bash**. Потом закрыть терминал крестиком и открыть заново, чтобы новый профиль подхватился.

Если Git Bash в списке нет, значит Git еще не установлен или установлен после запуска VS Code. Поставь Git и перезапусти VS Code целиком.

### Проверка, что все встало

В терминале VS Code по очереди набрать:

```bash
python --version
git --version
```

Должны ответить номерами версий, например `Python 3.13.12`. Если вместо этого открылся магазин приложений или написано, что команда не найдена, значит галочка PATH не стояла. Переустановить Python с галочкой и открыть терминал заново: старое окно терминала о новых программах не знает.

## Шаг 2. Скачать проект группы

В терминале, в той папке, где хочешь держать проекты:

```bash
git clone https://github.com/timkiberone8-eng/python-calculator.git uchebnik
cd uchebnik
```

Последнее слово `uchebnik` это имя папки на твоем компьютере. Без него папка назвалась бы `python-calculator`, а это имя понадобится твоему собственному проекту на шаге 6.

**Это учебник, а не тетрадь.** Здесь лежит код группы: его читают, запускают и отматывают по шагам. Свой код ты пишешь в отдельном проекте на своем аккаунте, про это шаг 6. В учебнике ничего не сохраняй и не отправляй: он принадлежит не тебе.

`git clone` не просто скачивает файлы, он забирает вместе с ними всю историю проекта: все сохранения от первого занятия до последнего. Поэтому дальше у тебя работают команды из шагов 4 и 6, и видно не только как код выглядит сейчас, но и как он таким стал.

**Про `git init`, если встретишь эту команду.** Она включает историю в обычной папке, где ее раньше не было: папка становится проектом, за которым Git следит. Именно так группа заводила свои проекты на первом занятии, с пустого места. Здесь она не нужна, в склонированном проекте история уже есть. Понадобится, когда будешь начинать свой собственный проект с нуля.

Открыть папку в VS Code: меню File, пункт Open Folder, выбрать папку проекта.

## Шаг 3. Запустить

В терминале VS Code, находясь в папке проекта:

```bash
python session2/main.py
```

Файлы проекта разложены по папкам занятий: `session1`, `session2` и дальше. Калькулятор лежит в `session2`, что в остальных папках, написано в README.

Программа спросит два числа и операцию. Попробуй по очереди:

- `5`, `3`, `сложение` даст `Результат: 8.0`
- `5`, `0`, `деление` даст «Ошибка: деление на ноль невозможно!» и не упадет
- `привет` вместо числа даст «Ошибка: введено не число!»
- `-9`, потом любое второе число, потом `квадратный корень` даст «Ошибка: корень из отрицательного числа не определён». Второе число программа спрашивает всегда, даже когда оно не нужно: это известная недоделка, чинить ее будем вместе

Три последних случая это и есть смысл уроков 2 и 3: программа не ломается от неправильного ввода, а объясняет, что не так.

**Важно про кнопку запуска.** В VS Code есть зеленый треугольник Run. Для этого проекта он не подходит: вывод уходит в панель, куда нельзя печатать, и программа падает на первом же вопросе с ошибкой `EOFError`. Запускать командой в терминале.

## Шаг 4. Пройти по шагам занятий

Проект собран так, что каждое сохранение в истории это один шаг занятия, и на каждом шаге программа работает. Посмотреть список:

```bash
git log --oneline
```

Снизу вверх это путь группы с первого занятия. Перемотать проект на любой шаг:

```bash
git checkout <первые буквы и цифры строки>
```

Последняя команда возвращает проект в конец, к самой свежей версии. Делай так после каждого просмотра, иначе запутаешься, где находишься.

В старых шагах папок занятий еще нет, все файлы лежат прямо в папке проекта: раскладка по занятиям появилась позже. Поэтому там `python main.py`, а в последней версии `python session2/main.py`.

На первой команде Git напишет длинное предупреждение со словами `detached HEAD`. Это нормально: он сообщает, что ты смотришь на старую версию, а не на последнюю.

| Шаг | Что смотреть | Что нового |

Читай не только код, но и комментарии в нем. Они написаны как объяснение, а не как пометки для себя.

## Шаг 5. Представиться Git

Сделать это надо до первого сохранения, иначе Git откажется работать. Дословно, проверено на чистой установке:

```
Author identity unknown

*** Please tell me who you are.

Run
  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"
```

Причина простая: каждое сохранение подписывается именем и почтой того, кто его сделал. Это не формальность, а то, как в общем проекте видно, чей код. Git не выдумывает подпись за тебя и молча подставлять чужую тоже не станет, поэтому и останавливается.

Один раз на своем компьютере:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "твоя@почта"
```

Почту ставь ту же, на которую заведен (или заведешь на шаге 6) аккаунт github.com, тогда твои сохранения на сайте будут привязаны к твоему профилю, а не висеть безымянными.

Посмотреть, что получилось, и поправить опечатку:

```bash
git config --global --list    # показать все настройки списком
git config --global -e        # открыть файл настроек в редакторе
```

Вторая команда открывает обычный текстовый файл, где все это лежит. Полезно посмотреть хотя бы раз, чтобы «настройки Git» перестали быть магией: это несколько строк в файле.

**Про `--global` и общие компьютеры.** Слово `--global` означает «для всех моих проектов на этом компьютере». Дома это правильно: компьютер твой, работаешь на нем только ты.

В классе наоборот: за одной машиной по очереди сидят разные люди, и там мы задаем имя **без** `--global`, отдельно в каждом проекте.

## Шаг 6. Своя тетрадь: аккаунт и свой проект

Свой код живет в отдельном проекте, на твоем собственном аккаунте GitHub.

**Аккаунт.** Зарегистрироваться на github.com: почта, пароль, логин. На почту придет код, его надо ввести, иначе аккаунт не заработает. Письмо часто попадает в «Спам». Логин запиши, он понадобится ниже.

**Свой проект на сайте.** Войдя в аккаунт, нажать плюс справа вверху, пункт New repository. Имя `python-calculator`, как у всей группы. Поставить галочку **Add a README file**, нажать Create repository.

**Скачать его к себе.** В терминале выйти из учебника в общую папку и склонировать свой проект:

```bash
cd ..
git clone https://ЛОГИН@github.com/ЛОГИН/python-calculator.git
cd python-calculator
```

Вместо `ЛОГИН` в обоих местах подставь свой логин на GitHub. Первый, перед `@`, не опечатка: он говорит Git, от чьего имени отправлять работу. Если на компьютере уже кто-то входил в GitHub, без него Git молча возьмет чужой вход, и отправка закончится ошибкой 403.

Теперь рядом лежат две папки: `uchebnik` (читать) и `python-calculator` (писать). Дальше все сохранения делаются во второй.

При первой отправке, командой `git push` ниже, откроется окно входа в GitHub. Войди своим логином и паролем, дальше компьютер это запомнит.

### Три команды, которыми мы сохраняем работу

Это то, чем занятие заканчивается каждый раз, так что стоит понимать заранее. Делается в тетради, в папке `python-calculator`.

Git это программа, которая хранит историю проекта. Не «последнюю версию файла», а все сохранения подряд, с подписью и датой, так что в любое из них можно вернуться. Именно ее историю ты смотрел на шаге 4.

Сохранение делается в три приема, и у каждого своя работа:

```bash
git add .
git commit -m "Добавил показ списка книг"
git push
```

| Команда | Что делает | Понятной метафорой |
|---|---|---|
| `git add .` | отмечает, какие файлы попадут в сохранение. Точка означает «все измененные» | сложить вещи в коробку |
| `git commit -m "..."` | делает само сохранение и записывает к нему подпись | заклеить коробку и подписать маркером, что внутри |
| `git push` | отправляет сохранения на github.com | отнести коробку на склад, откуда ее видно всем и откуда ее можно забрать с другого компьютера |

Сообщение в кавычках пишется не для галочки. Через месяц история читается как список «что я делал», и строчки вроде `1`, `2`, `save` в нем бесполезны. Пиши, что изменилось: `Добавил удаление книги`, `Починил деление на ноль`.

Две первые команды работают **без интернета и без всякого аккаунта**: история хранится прямо в папке проекта. Аккаунт нужен только третьей, `git push`. Так что если с почтой или регистрацией не сложилось, заведи тетрадь обычной папкой, это как раз тот случай для `git init`:

```bash
mkdir python-calculator
cd python-calculator
git init
```

Сохраняться в ней можно так же, ничего не потеряется, а отправим на занятии.

Посмотреть, что получилось:

```bash
git log --oneline    # список сохранений, самое свежее сверху
git status           # что изменено прямо сейчас и попадет в следующее сохранение
```

Первое время удобнее смотреть это картинкой, тем самым Git Graph.

## Если что-то не работает

| Что видно | В чем дело | Что сделать |
|---|---|---|
| `python` не найден, открылся магазин приложений | не стояла галочка Add python.exe to PATH | переустановить Python с галочкой, открыть новое окно терминала |
| `EOFError: EOF when reading a line` | запуск зеленой кнопкой вместо терминала | набрать `python session2/main.py` в терминале |
| `FileNotFoundError: example.txt` в файлах урока 4 | программы урока 4 ищут файл рядом с собой | сначала `cd session3/urok4`, потом `python read_example.py` |
| `can't open file` и в конце `main.py` | калькулятор лежит не в корне, а в папке `session2` | из папки проекта набрать `python session2/main.py` |
| `ModuleNotFoundError` | запуск не из той папки | вернуться в папку проекта командой `cd`, запускать `python session2/main.py` оттуда |
| `git push` отвечает `Permission ... denied to` и чужим логином, или `403` | Git взял вход, который уже был сохранен на компьютере, либо ты отправляешь в учебник | `git remote -v` покажет адрес. В нем должен быть твой логин дважды: `git remote set-url origin https://ЛОГИН@github.com/ЛОГИН/python-calculator.git` |

Если застрял дольше чем на двадцать минут, не сиди: запиши, что именно написано на экране, и покажи на занятии. Умение прочитать сообщение об ошибке и есть половина программирования, этому мы как раз учимся.

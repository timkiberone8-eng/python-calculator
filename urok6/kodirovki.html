Почему в psql ломаются русские буквы

При входе в SQL Shell на Windows появляется вот это:

psql (18.6) ПРЕДУПРЕЖДЕНИЕ: Кодовая страница консоли (866) отличается от основной страницы Windows (1251). 8-битовые (русские) символы могут отображаться некорректно. Введите "help", чтобы получить справку. postgres=#

Что такое «кодовая страница», откуда взялись 866 и 1251 и почему это важно?

Компьютер не знает букв. Он хранит числа.

Чтобы превратить число в букву, нужна таблица. Она называется кодовая страница. Беда в том, что таблиц для русского языка несколько.

А
таблица 866
128
таблица 1251
192

Нажми на букву: одна и та же буква — разные числа.

Два друга с разными шифрами

Окно консоли записывает буквы по таблице 866, а psql читает их по таблице 1251.

Окно консоли отправляет

psql получает

Никто не ошибся: каждый честно пользуется своей таблицей. Просто таблицы разные.

Проверим, что попадёт в базу

набираешь
окно отправляет
psql читает как
postgres=# SELECT ''; → postgres=# SELECT upper(''); →

Результаты для «аня» проверены на настоящем PostgreSQL 18.

Лечение: одна команда

\! chcp 1251

\!

«psql, передай эту команду Windows»

chcp

CHange Code Page — «сменить кодовую страницу». Команда Windows со времён DOS.

1251

Какую таблицу взять. Ту же, что у psql. Теперь шифр общий.

Запомни

  • Видишь предупреждение про кодовую страницу → первой командой \! chcp 1251
  • Команда действует, пока окно открыто. Закрыл окно — при следующем запуске вводишь снова.
  • Проверка: SELECT upper('аня'); должно дать АНЯ, а не ан╧
  • Опасно то, что без chcp на экране всё выглядит нормально. Ломается то, что лежит в базе.

Почему так вышло: в 80-х каждая страна придумывала свою таблицу. Сейчас есть одна на все языки — UTF-8. В ней работают телефоны, браузеры и Linux, поэтому там такой проблемы нет.

# Занятие 5: базы данных. Конспект

Для тех, кто пропустил занятие 4 октября: часть занятия про базы данных, по порядку и с объяснениями. В конце олимпиадные задачи, с которых занятие началось.

Читай и каждую команду выполняй у себя. Под командой написано, что ответит psql. Совпало, иди дальше. Не совпало, загляни в раздел [«Если что-то пошло не так»](#если-что-то-пошло-не-так) в конце.

Когда дойдёшь до конца, переходи к [закреплению](zakreplenie.html#2-найди-ошибку): там ошибки с занятия и задачи с ответами.

## 1. Вход

SQL Shell это окно, а psql это программа в нём, через которую ты разговариваешь с базой: набираешь команду, она отвечает. Если поставить PostgreSQL негде, просто читай: всё, что ответит psql, есть на этой странице.

{% include psql-vhod.md konspekt=true %}

### Что ответит psql

На экране после трёх команд будет так. Слева от `#` пишет psql, справа то, что набрал ты. Строка без `#` это ответ psql:

```
postgres=# \! chcp 1251
Текущая кодовая страница: 1251
postgres=# CREATE DATABASE kiber;
CREATE DATABASE
postgres=# \c kiber
Вы подключены к базе данных "kiber" как пользователь "postgres".
```

`\!` значит «psql, передай эту команду Windows», а `chcp 1251` переключает окно на ту же кодовую страницу, что у psql. Без неё русские буквы портятся по дороге в базу, причём на экране всё выглядит нормально. Как это происходит, показывают слайды.

Проверь, что сработало:

```sql
SELECT upper('аня');
```

`upper` делает буквы большими. Должно получиться:

```
 upper
-------
 АНЯ
(1 строка)
```

Если вместо `АНЯ` каша вроде `ан╧`, набери `\! chcp 1251` ещё раз. Команда действует, пока окно открыто: закрыл SQL Shell, в следующий раз набираешь снова.

После `\c kiber` строка внизу стала `kiber=#`. Имя перед `=#` показывает, в какой базе ты сейчас работаешь. На занятии для всей работы завели базу `kiber`. Если назовёшь свою `kiber`, тогда всё на экране совпадёт с этой страницей и с закреплением.

## 2. Что такое таблица

База хранит данные в таблицах. Таблица похожа на лист Excel или на CSV-файл, в который на занятии 20 сентября сохраняли книги в «Моей библиотеке»: каждая строка это одна запись, каждый столбец это одно свойство записи. Сегодня это таблица учеников, и после раздела 4 она будет выглядеть так:

| id | name | age | birthday | is_active |
|---|---|---|---|---|
| 1 | Anna | 15 | 2010-03-15 | true |
| 2 | Petr | 16 | 2009-11-02 | true |
| 3 | Olga | 14 | 2011-06-20 | false |

`name` имя, `age` возраст, `birthday` день рождения, `is_active` ходит ли сейчас на занятия, `id` номер ученика.

Главное отличие от CSV. В CSV-файл можно записать что угодно: слово вместо возраста, 30 февраля вместо даты. Ошибка вылезет потом, когда программа начнёт это читать. В базе у каждого столбца есть **тип**, и база проверяет каждое значение в момент записи. Как это выглядит, увидишь в разделе 7.

Имена латиницей, как на занятии: если русские буквы всё-таки сломаются, каша не попадёт в базу.

## 3. Создать таблицу: CREATE TABLE

Эту команду скопируй кнопкой в правом верхнем углу блока и вставь в SQL Shell правой кнопкой мыши:

<div class="copyable" markdown="1">

```sql
CREATE TABLE students (
  id SERIAL PRIMARY KEY,
  name TEXT,
  age INTEGER,
  birthday DATE,
  is_active BOOLEAN
);
```

</div>

psql ответит:

```
CREATE TABLE
```

Как она устроена:

- `CREATE TABLE students` значит «создай таблицу с именем `students`».
- В скобках столбцы через запятую. У каждого сначала имя, потом тип.
- После последнего столбца запятой нет. Вся команда кончается `;`.

Слова SQL (`CREATE`, `TABLE`, `INSERT`, `SELECT`) пишут большими буквами, чтобы они отличались от имён. psql поймёт и маленькие.

Типы с занятия:

| Тип | Что хранит | Как пишется значение |
|---|---|---|
| `INTEGER` | целое число | `15` |
| `TEXT` | текст | `'Anna'`, в одинарных кавычках |
| `DATE` | дату | `'2010-03-15'`: год, месяц, день, в кавычках |
| `BOOLEAN` | да или нет | `true` или `false`, без кавычек |
| `SERIAL` | номер, который база ставит сама: 1, 2, 3 и дальше | никак, его не пишут |

`PRIMARY KEY` (первичный ключ) значит, что в этом столбце у каждой строки своё значение: двух строк с одинаковым `id` база не допустит. Зачем это нужно: в группе могут оказаться две Анны пятнадцати лет, и различить их можно будет только по номеру. Поэтому почти в каждой таблице первым столбцом идёт `id SERIAL PRIMARY KEY`: номер ставится сам и не повторяется.

### Почему строка перед курсором меняется

Пока ты вставляешь команду, в начале каждой строки пишет psql:

```
kiber=# CREATE TABLE students (
kiber(#   id SERIAL PRIMARY KEY,
kiber(#   name TEXT,
kiber(#   age INTEGER,
kiber(#   birthday DATE,
kiber(#   is_active BOOLEAN
kiber(# );
CREATE TABLE
```

`kiber(#` значит «скобка открыта, жду продолжения»: Enter не отправил команду в базу, а только перенёс строку. Команда уходит, когда psql видит `;`, а все скобки и кавычки закрыты.

{% include psql-klavishi.md konspekt=true %}

Проверь, что таблица появилась:

```sql
\dt
```

`\dt` показывает таблицы той базы, к которой ты подключён:

```
             Список таблиц
 Схема  |   Имя    |   Тип   | Владелец
--------+----------+---------+----------
 public | students | таблица | postgres
(1 строка)
```

Столбцы «Схема» и «Владелец» пока не нужны. Главное, что `students` в списке есть.

## 4. Добавить строки: INSERT

Дальше команды набирай руками: так они быстрее запоминаются.

Сначала одна строка:

```sql
INSERT INTO students (name, age, birthday, is_active) VALUES ('Anna', 15, '2010-03-15', true);
```

Читается так: «вставь в таблицу `students`, в столбцы `name`, `age`, `birthday`, `is_active`, значения `'Anna'`, `15`, `'2010-03-15'`, `true`». Значения встают в столбцы по порядку: первое в первый, второе во второй. Поэтому их ровно столько же, сколько столбцов в первых скобках.

`id` в списке нет: его база поставит сама, на то он и `SERIAL`.

psql ответит:

```
INSERT 0 1
```

`1` значит, что добавлена одна строка. `0` служебный, на него не смотри.

Теперь две строки одной командой: после `VALUES` скобки через запятую, `;` только в самом конце. Удобнее всего ставить каждую запись на свою строку, как ниже. Enter до `;` команду не отправляет, а только переносит строку, как в `CREATE TABLE`. Зато сразу видно, где кончается один ученик и начинается другой, и легко не запутаться в скобках и запятых:

```sql
INSERT INTO students (name, age, birthday, is_active) VALUES
  ('Petr', 16, '2009-11-02', true),
  ('Olga', 14, '2011-06-20', false);
```

```
INSERT 0 2
```

Привыкай смотреть на число в ответе. Оно первым показывает, что команда сделала не то, что ты хотел.

### Почему список столбцов пишут всегда

Список столбцов после имени таблицы можно и не писать. Тогда значения ложатся в столбцы подряд, в том порядке, в каком столбцы стоят в таблице. Перепутаешь порядок, и значение ляжет не туда.

Иногда база это заметит. У `students` первый столбец `id`, и без списка `'Ivan'` попадёт в него. Попробуй:

```sql
INSERT INTO students VALUES ('Ivan', 16, '2009-05-01', true);
```

```
ОШИБКА:  неверный синтаксис для типа integer: "Ivan"
СТРОКА 1: INSERT INTO students VALUES ('Ivan', 16, '2009-05-01', true)...
                                       ^
```

Как читать ошибку. Первая строка говорит, что не так: `Ivan` нельзя превратить в целое число (`integer` это `INTEGER`), поэтому база отказывает. `СТРОКА 1` и стрелка `^` под ней показывают, где psql споткнулся. Длинную команду psql показывает не целиком, а куском вокруг ошибки, с многоточием.

Хуже, когда у перепутанных столбцов один тип. В закреплении будет таблица игр, в ней первым идёт название, вторым жанр, оба текстом. Вот игра, у которой их перепутали (это только пример, таблицы игр у тебя пока нет):

```sql
INSERT INTO games VALUES ('sandbox', 'Minecraft', 2011, 9.0, false);
```

```
INSERT 0 1
```

Ошибки нет. В таблице теперь игра «sandbox» в жанре «Minecraft», и ты этого не заметишь, пока не посмотришь. Со списком столбцов видно, какое значение куда идёт:

```sql
INSERT INTO games (title, genre, year, rating, is_free) VALUES ('Minecraft', 'sandbox', 2011, 9.0, false);
```

Поэтому список столбцов пишут всегда.

## 5. Посмотреть: SELECT

```sql
SELECT * FROM students;
```

«Выбери все столбцы из таблицы `students`». Звёздочка `*` значит «все столбцы».

```
 id | name | age |  birthday  | is_active
----+------+-----+------------+-----------
  1 | Anna |  15 | 2010-03-15 | t
  2 | Petr |  16 | 2009-11-02 | t
  3 | Olga |  14 | 2011-06-20 | f
(3 строки)
```

Номера `1`, `2`, `3` база поставила сама. `true` и `false` psql показывает коротко: `t` и `f`. Внизу число строк.

Чтобы увидеть только некоторые столбцы, перечисли их через запятую вместо звёздочки:

```sql
SELECT name, age FROM students;
```

```
 name | age
------+-----
 Anna |  15
 Petr |  16
 Olga |  14
(3 строки)
```

## 6. Отобрать строки: WHERE

`WHERE` («где») оставляет только те строки, для которых условие верно:

```sql
SELECT name, age FROM students WHERE age > 14;
```

```
 name | age
------+-----
 Anna |  15
 Petr |  16
(2 строки)
```

Olga не попала: ей 14, а 14 не больше 14.

Сравнения:

| Знак | Значит |
|---|---|
| `=` | равно |
| `>` и `<` | больше и меньше |
| `>=` и `<=` | больше или равно, меньше или равно |

Текст сравнивается буква в букву, и большие буквы отличаются от маленьких:

```sql
SELECT * FROM students WHERE name = 'anna';
```

```
 id | name | age | birthday | is_active
----+------+-----+----------+-----------
(0 строк)
```

Ошибки нет, просто ни одной строки: в таблице записано `'Anna'`, с большой буквы.

### AND и OR

Условий может быть несколько. `AND` («и»): строка попадает, только если верны **оба** условия. `OR` («или»): хватает **одного**.

Прежде чем выполнять, угадай, кто окажется в каждом ответе:

```sql
SELECT name FROM students WHERE age > 14 AND is_active = true;
SELECT name FROM students WHERE age < 15 OR is_active = false;
```

<details markdown="1">
<summary markdown="span">Показать ответ</summary>

```
 name
------
 Anna
 Petr
(2 строки)
```

Anna и Petr старше 14 и ходят на занятия, у обоих верны оба условия. У Olga не верно ни одно.

```
 name
------
 Olga
(1 строка)
```

Olga младше 15 и не ходит на занятия. Ей хватило бы и одного из двух. У Anna и Petr не верно ни одно: им не меньше 15, и они ходят.

</details>

### Порядок: ORDER BY

```sql
SELECT name, age FROM students ORDER BY age;
```

```
 name | age
------+-----
 Olga |  14
 Anna |  15
 Petr |  16
(3 строки)
```

`ORDER BY age` выстраивает строки по возрасту, от меньшего к большему. Чтобы наоборот, добавь `DESC`:

```sql
SELECT name, age FROM students ORDER BY age DESC;
```

```
 name | age
------+-----
 Petr |  16
 Anna |  15
 Olga |  14
(3 строки)
```

## 7. Что база не пропустит

У каждого столбца свой тип, и база проверяет каждое значение. Одну такую проверку ты уже видел в разделе 4: имя `'Ivan'` не пустили в `id`, потому что слово не превращается в число. Вот ещё две. Сначала угадай, что ответит psql:

```sql
INSERT INTO students (name, birthday) VALUES ('Ivan', '2010-02-30');
INSERT INTO students (name, is_active) VALUES ('Ivan', 'da');
```

```
ОШИБКА:  значение поля типа date/time вне диапазона: "2010-02-30"
СТРОКА 1: ...RT INTO students (name, birthday) VALUES ('Ivan', '2010-02-3...
                                                               ^
```

30 февраля не бывает, а в столбец `DATE` можно записать только настоящую дату.

```
ОШИБКА:  неверный синтаксис для типа boolean: "da"
СТРОКА 1: ...NSERT INTO students (name, is_active) VALUES ('Ivan', 'da');
                                                                   ^
```

В `BOOLEAN` можно только `true` или `false`.

Теперь посмотри таблицу:

```sql
SELECT * FROM students;
```

Ивана там нет ни разу. Если в команде ошибка, база не записывает из неё ничего, даже правильную часть. Так данные в базе не портятся. В CSV-файл 30 февраля записалось бы молча.

<details markdown="1">
<summary markdown="span">Подробнее: всегда ли база отказывает</summary>

Нет. База отказывает, только когда значение невозможно превратить в нужный тип. `'15'` в кавычках это текст, но из него получается число, и база сама превратит его в `15`. А `15.7` в столбце `INTEGER` молча округлится до `16`, без всякой ошибки. Поэтому числа пиши без кавычек и смотри, какой тип у столбца.

</details>

## 8. Добавить столбец: ALTER TABLE

Таблицу можно менять и после того, как в ней появились данные. Добавим столбец `grade`, класс в школе:

```sql
ALTER TABLE students ADD COLUMN grade INTEGER;
```

`ALTER TABLE` значит «измени таблицу», `ADD COLUMN` «добавь столбец», дальше имя и тип, как в `CREATE TABLE`. psql ответит:

```
ALTER TABLE
```

Посмотри, что получилось:

```sql
SELECT * FROM students;
```

```
 id | name | age |  birthday  | is_active | grade
----+------+-----+------------+-----------+-------
  1 | Anna |  15 | 2010-03-15 | t         |
  2 | Petr |  16 | 2009-11-02 | t         |
  3 | Olga |  14 | 2011-06-20 | f         |
(3 строки)
```

У старых строк новый столбец пустой: значения там нет. В SQL такая пустота называется `NULL`. Заполним его в следующем разделе.

## 9. Изменить: UPDATE

```sql
UPDATE students SET grade = 9 WHERE name = 'Anna';
```

«Измени таблицу `students`: поставь `grade` равным 9 там, где `name` равно `'Anna'`». psql ответит:

```
UPDATE 1
```

Изменена одна строка. Посмотри:

```sql
SELECT * FROM students;
```

```
 id | name | age |  birthday  | is_active | grade
----+------+-----+------------+-----------+-------
  2 | Petr |  16 | 2009-11-02 | t         |
  3 | Olga |  14 | 2011-06-20 | f         |
  1 | Anna |  15 | 2010-03-15 | t         |     9
(3 строки)
```

Anna переехала в конец. Это нормально: без `ORDER BY` база выдаёт строки в том порядке, в каком ей удобно, и после изменения он может поменяться. Нужен определённый порядок, пиши `ORDER BY`.

**Без `WHERE` меняются все строки.** Сделай так нарочно, таблица учебная:

```sql
UPDATE students SET grade = 10;
```

```
UPDATE 3
```

Теперь десятый класс у всех троих. Кнопки «отменить» у базы нет: что выполнилось, то записано. Отсюда правило с занятия: в `UPDATE` и `DELETE` сначала пиши `WHERE`, потом всё остальное, а после выполнения смотри на число в ответе. Ждал 1, а пришло 3, значит, команда задела лишнее.

## 10. Удалить строки: DELETE

Перед удалением полезно посмотреть, что именно удалишь: выполни `SELECT` с тем же `WHERE`.

```sql
SELECT name FROM students WHERE is_active = false;
```

```
 name
------
 Olga
(1 строка)
```

Под условие попадает одна Olga. Теперь удаляем:

```sql
DELETE FROM students WHERE is_active = false;
```

```
DELETE 1
```

`SELECT * FROM students;` покажет двоих. `DELETE` без `WHERE` удалил бы всех учеников разом.

## 11. Удалить таблицу: DROP TABLE

```sql
DROP TABLE students;
```

```
DROP TABLE
```

Проверь командой `\dt`:

```
Никакие таблицы не найдены.
```

Чем это отличается от `DELETE`. `DELETE` удаляет строки, а таблица со столбцами остаётся, и её можно заполнять снова. `DROP TABLE` удаляет таблицу целиком: строки, столбцы и само имя. Отмены нет и здесь.

На занятии после этого то же самое тренировали на второй таблице, с самолётами. У тебя такая тренировка будет в закреплении, на таблице игр.

Условие и поле для расстановки на [отдельной странице](strazhniki.html). Нажимаешь на перекрёсток, чтобы поставить или убрать стражника, а страница считает стражников на каждой улице.

<summary markdown="span">Подсказка с занятия</summary>

### Калькулятор

У исполнителя Калькулятор две команды:

1. вычти 3
2. умножь на 2

Составь программу не длиннее 5 команд, которая из числа 5 получает 25. Записывай только номера команд. Например, программа `22221` из числа 1 получает 13.

**Проверь себя:** выполни свою программу по шагам, начиная с 5. Должно получиться 25.

### Перетасовка таблицы

Было:

| 1 | 2 | 3 |
| 4 | 5 | 6 |
| 7 | 8 | 9 |

Нужно получить:

| 9 | 7 | 8 |
| 6 | 4 | 5 |
| 3 | 1 | 2 |

Можно менять местами любые две строки и любые два столбца. Можно ли из первой таблицы получить вторую? Если да, то за наименьшее число перестановок.

**Проверь себя:** проделай свои перестановки на бумаге и сравни результат со второй таблицей.

## Если что-то пошло не так

| Что видишь | В чём дело | Что сделать |
|---|---|---|
| psql ничего не делает, строка стала `kiber-#`, `kiber(#` или `kiber'#` | команда не закончена: нет `;`, открыта скобка или кавычка | таблица приглашений в разделе [«Почему строка перед курсором меняется»](#почему-строка-перед-курсором-меняется) |
| `ошибка синтаксиса` | лишняя или пропущенная запятая, скобка, кавычка | стрелка `^` под командой показывает, где искать. Исправь и выполни заново |
| `отношение "students" уже существует` | таблица `students` уже есть, ты её создавал. «Отношением» psql называет таблицу | `DROP TABLE students;` и снова с раздела 3 |
| `отношение "students" не существует` | таблицы `students` здесь нет: ты не в той базе (строка начинается с `postgres=#`) или таблица уже удалена | `\c kiber`, потом `\dt` |
| `база данных "kiber" уже существует` | базу ты уже создавал | `\c kiber` |
| вместо `АНЯ` каша вроде `ан╧` | после входа не было `\! chcp 1251` | набери её |
| SQL Shell закрылся | нажат Ctrl+Z или Ctrl+C | открой заново, войди, `\! chcp 1251`, `\c kiber`. Всё, что уже выполнилось, на месте |

Если ничего не помогло, сфотографируй экран с ошибкой и покажи на занятии.
